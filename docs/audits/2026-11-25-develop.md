# Develop bug hunt, 25 November 2026 (ORCH-2006)

Four defects reproduced on macOS at `3a2a248c8`. The November 24–25 range
(`f30ff3944..3a2a248c8`) contained 28 first-parent landings and 106
“Merge queue: take in” commits. This was a risk-based sample, not a test of
every PR or a native Windows run.

| Bug | Reproduction | Control |
| --- | --- | --- |
| **ORCH-2008: overlapping sync requests disagree about a failed pass** (`a3b246bc6`) | Start two `sync now --json` CLI callers in separate processes before the loop polls. A and B each write a wake token. Let the loop consume the wake and finish one simulated offline pass. B gets `{"last_error":"offline"}` and exits 2; A waits out the deadline, gets `{"woken":true}` and exits 0. No wake remains. | In the same harness, A alone receives the offline result and exits 2. The probe kept the loop marked alive and shortened the deadline to eight seconds. No remote or extra pass was needed. |
| **ORCH-2009: the current-file preview calls a present file missing** (`8287dde08`) | Save a small `report.md` as task evidence, then replace the source with 524,289 bytes of UTF-8 text. The result row marks it changed; `reffiles.read_source` returns 404, “This file is not in the project any more.” The preview displays the response body. | At 524,288 bytes the same row is marked changed and the endpoint returns 200 with all bytes. The defect is the false deletion message, not the preview cap. |
| **ORCH-2010: replacing a source can leave the changed-evidence hint stale** (`8287dde08`) | Warm `tickets.proof_changed` on a source and evidence copy containing `old\r\n`. Atomically replace the source with `new\r\n`, preserving the mtime. The next live row still omits the changed hint although `read_source` serves the new bytes. | Clearing the comparison cache immediately yields `True`. Restoring the two revisions from ZIP members with the same timestamp reproduced this with different inodes; touching the source also restored the hint. |
| **ORCH-2011: retry refuses an interrupted core skill copy** (`108ca170e`) | In a disposable process, limit output file size to 4,096 bytes while `_copy_dir` copies a 56,000-byte `SKILL.md`. Delay the file copy until after the marker timestamp. The OS raises `EFBIG` and leaves 4,096 bytes. Lift the limit and call `link_skill`: it refuses the truncated file as “not orch's”. | An uninterrupted copy is recognized as owned. The existing interruption test fails *between* files, before any bytes of the next file are written. Windows always takes this copy path; macOS takes it when linking is unavailable. |

Claude Opus 5.5 challenged all four observations. The single-caller control,
exact preview boundary, ZIP replacement and OS-enforced short write distinguish
the defects from a legitimate timeout, an intentional size limit, an ordinary
edit, and a failure before writing. The two existing core controls for evidence
edits and interrupted copies passed; neither covers the failing case above.
Each bug has its own ticket and repair brief. No product behavior changed here.
