## orch workspace
Track every piece of work as an orch ticket: `orch ticket list`, else `orch ticket new "<title>"`; then one task per piece of the person's work, in plain words (no ids, paths or commands) (`orch check add <id> "<step>"`) BEFORE you start. A step is done only with proof: `orch check done <id> <c> --command "<what you ran>"` (or --note, --pr, --commit, --file, --url) and `--summary "<what came out, one line>"`. Files you make go in `orch ticket artifacts-dir <id>`.
Need a decision or blocked: `orch ask <id> "<question>" --option A --option B --recommend A`, then stop. End every run with `orch ticket summary <id> "<what was done and what is left>"` for the person, in plain words. When the ticket reaches Review, orch sends its summary and files to the person by itself: add no task for that and don't write that it was sent. Answering a person's message is still your job. Details: `.agents/skills/orch/SKILL.md`.

Ticket statuses are Backlog, Ready, Working, Waiting, Review, Done, and Dropped. When the work is finished set the ticket to done: orch moves it to Review for a person to check; never wait for or claim it is Done. If `orch look show` says nobody picked an icon, choose one from `orch look list` and run `orch look set --icon <id> --color <token>`; never change a person's pick.
