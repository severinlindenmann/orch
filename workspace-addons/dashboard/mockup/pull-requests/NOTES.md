# Pull requests add-on notes

## pull-requests.html: Pull requests (add-on nav tab)
- Draft B "Queue first" picked by the owner (ORCH-746, 19 Nov; before: draft A of ORCH-432, text lists and one long table). Top: one merge queue per repository and base branch as a left-to-right flow (block `flow`): Being checked (the group, its pull requests as chips, a progress bar against the usual check time) → In line (count, longest wait, chips with their place, paused ones yellow) → Merged lately (x of y groups, the last merged as green chips, one small bar per recent group: green merged, yellow in part, red sent back). Every chip opens the pull request on GitHub; the title opens the repository's pull requests. Then two charts side by side (block `chart`): Opened and merged per day, and How the merge queue went (stacked merged / sent back), 14 days, numbers on hover. Then one compact table "Open pull requests" with tabs by State and counts, 15 rows under All then "Show N more": # (GitHub), Pull request (the ticket), What is going on, Ticket (the ticket), State (a coloured chip for Checks failed, Has a conflict, Ready to merge), In line for. A footnote says what the merge queue does. Filled by `orch pull-requests view`; sample text is `e2e/fixtures/pull-requests-page.json`; the loaded view here is the real dashboard's rendering of it (e2e/dash_pull_requests.cjs), so the tabs and hover do not work in this static copy.
- States: loaded (default), loading (`?state=loading`), empty (`?state=empty`: one empty state "No pull requests yet" and the footnote).
- Not running: no preview state yet (the kit has no CSS for a third state). The real page adds above the stats `<div class="banner attn"><p class="grow">Pull requests are not being read right now, so what you see may be old.</p><button type="button" class="btn outline sm">Start reading</button></div>`; the table stays visible.
- A failed check says whether a helper runs on its linked ticket, read from the helper runs only (ORCH-1859): loaded shows "No helper running on BIL-1. Open the ticket to fix it."; with a live run on that ticket "A helper is running on BIL-1, maybe not on this check."; when the runs could not be read "Helper status on BIL-1 could not be checked; tries again by itself." (the page reloads its view every 15 s). An open ticket alone never reads as a helper coming. A failed pull request with no ticket says "No ticket is linked: make a ticket for it so a helper can fix it." Only the words change: row place, tab, ticket and links stay. The fixture views `helper_live` and `helper_unknown` hold the two other words; this static copy shows the loaded one.
