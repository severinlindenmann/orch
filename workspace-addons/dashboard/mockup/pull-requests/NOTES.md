# Pull requests add-on notes

## pull-requests.html: Pull requests (add-on nav tab)
- Draft A picked by the owner (ORCH-432, 18 Nov), with the merge queue shown per project. Top: one "Merge queue: <repository>" list per repository and base branch (meta "into <base> · groups of up to <max_group>"): a row per group being checked ("Group of 2 · checks running 12 min", its pull requests underneath) and one row for the line ("1 waiting in line · longest 49 min", "Next: ..."). Nothing in the queue: one "Merge queue" block with an empty state, shown only beside open pull requests. Then one table "Open pull requests" (meta "N open · N repositories"): Pull request (a quiet note under it only when there is one, else the repository when there are several), Ticket, State (Checks failed / Has a conflict / Being checked / 1st in line, paused / Ready to merge / Draft ...), In line for (since it joined the merge queue). Order: what needs someone, then the queue in its order, then the rest, drafts last. A footnote says what the merge queue does. No stat tiles. Filled by `orch pull-requests view`; sample text is `e2e/fixtures/pull-requests-page.json` (the mockup views are generated from it).
- States: loaded (default), loading (`?state=loading`), empty (`?state=empty`: one empty state "No pull requests yet" and the footnote).
- Not running: no preview state yet (the kit has no CSS for a third state). The real page adds above the stats `<div class="banner attn"><p class="grow">Pull requests are not being read right now, so what you see may be old.</p><button type="button" class="btn outline sm">Start reading</button></div>`; the table stays visible.
